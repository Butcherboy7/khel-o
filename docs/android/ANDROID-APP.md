# KHEL-O Android app — how it works and how to update it

The Play Store app is a **Trusted Web Activity (TWA)**: a small Android shell
(`android/`, generated by Google's Bubblewrap) that opens https://khel-o.com in
Chrome, full screen, with no address bar. Everything you see in the app is the
website.

## What updates when

| You change… | What to do | Play review? |
|---|---|---|
| Anything on the website (features, bug fixes, prices, copy) | Deploy the website as usual. The app shows it on next open. | No |
| App name, icon, splash colour, notification setting, Android permissions | Edit `android/twa-manifest.json`, then `bash android/build.sh --bump`, upload the new `.aab` | Yes (usually hours–1 day) |
| Google's yearly target-API rule (each August; API 36 from 31 Aug 2026) | `npm i -g @bubblewrap/cli@latest`, then `bash android/build.sh --bump`, upload | Yes |

## Files

- `android/twa-manifest.json` — the app's settings (package `com.khelo.app`,
  host `khel-o.com`, colours, icons, version). Source of truth.
- `android/build.sh` — builds `app-release-bundle.aab` (upload this to Play)
  and `app-release-signed.apk` (install directly on a phone). Both ignored by git.
- `android/generate.js` — regenerates the project from the manifest with icons
  from a local server. Only needed when icons aren't live on khel-o.com yet.
- `frontend/public/.well-known/assetlinks.json` — proves the app and the site
  belong together. **Without the right fingerprint here the app shows an
  address bar.** See "After the first Play upload" below.
- `frontend/public/manifest.json` + `frontend/public/icons/` — web app manifest
  and icons (`icon-maskable-*` are the padded ones Android crops into shapes).
- `frontend/src/app/offline/` — shown instead of Chrome's error page with no signal.
- `frontend/src/app/(legal)/delete-account/` — account deletion (Play requires
  it in-app and on the web). Backend: `backend/app/services/account_deletion_service.py`.

## The signing key (upload key)

Lives at `~/.khelo-android/` (`khelo-upload.keystore` + `SIGNING-KEY-README.txt`
with the password). **Never commit it** — the repo is public; `.gitignore`
blocks `*.keystore` / `*.jks`. Back both files up to a password manager.

Google Play keeps the real app-signing key ("Play App Signing"). Ours is only
the upload key; if it's lost, Play Console → Test and release → App integrity
→ "Request upload key reset".

## After the first Play upload — add Google's fingerprint (important)

Apps installed from Play are re-signed with Google's key, so `assetlinks.json`
must list **Google's** SHA-256 too, or Play users get an address bar:

1. Play Console → your app → Test and release → App integrity → App signing.
2. Copy "App signing key certificate → SHA-256 certificate fingerprint".
3. Add it to the `sha256_cert_fingerprints` array in
   `frontend/public/.well-known/assetlinks.json` (keep the existing upload-key one).
4. Deploy the website. Check: https://khel-o.com/.well-known/assetlinks.json and
   Google's tester:
   `https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://khel-o.com&relation=delegate_permission/common.handle_all_urls`

## One-time machine setup (already done on the main laptop, 2026-10-18)

- JDK 17: `%LOCALAPPDATA%\jdk\jdk-17.0.20.1+1` (portable Temurin zip).
- Android SDK via Google's `android` CLI (`%USERPROFILE%\AppData\AndroidCLI\android.exe`):
  `android sdk install platforms/android-36 build-tools/36.1.0 platform-tools cmdline-tools/19.0`.
  Bubblewrap needs `<sdk>\bin` to exist: it's a junction to `cmdline-tools\19.0\bin`.
- Emulator + system image + AVD live on `E:\AndroidSdkData` (junctioned back
  into the SDK and `~/.android/avd`) because C: is nearly full.
- `npm i -g @bubblewrap/cli@1.27.0`; `~/.bubblewrap/config.json` points at the JDK and SDK.

## Testing on the emulator

```bash
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd khelo_pixel -no-window -gpu swiftshader_indirect &
adb install -r android/app-release-signed.apk
adb shell monkey -p com.khelo.app -c android.intent.category.LAUNCHER 1
```

Before assetlinks.json is live you'll see an address bar. To preview full-screen
anyway, the emulator's Chrome was told to skip the check (test devices only):
`adb shell "echo '_ --disable-digital-asset-link-verification-for-url=\"https://khel-o.com\"' > /data/local/tmp/chrome-command-line"`
(in Git Bash prefix `MSYS_NO_PATHCONV=1`).
